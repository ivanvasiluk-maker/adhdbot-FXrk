# Подготовка SKILLER к запуску — короткие спринты

Задание Ивана от 3 октября 2026: сохранить существующую механику бота,
исправлять её небольшими проверяемыми частями. Предыдущий PR #139 уже в main.
Каждый спринт — отдельный PATCH и проверка. Этот документ не означает готовность
всего задания или обновление работающего бота.

## Спринт 1 — обращение (PATCH-45)

1. Сначала отдельный выбор «На ты» / «На вы».
2. Затем отдельный выбор «Мужской» / «Женский» / «Можно без рода».
3. Сохранение каждого выбора; изменение через /address возвращает прежний вопрос,
   сохраняя стадию разговора и ожидаемый ответ об упражнении. Старые кнопки принимаются.
4. Проверки всех шести сочетаний, продолжения после перезагрузки данных,
   ожидания второго ответа и известных ошибок согласования.

Используются существующие поля address_mode (ty/vy) и address_form
(male/female/neutral): второй источник настроек пола не добавляется.
Новые настройки применяет существующий общий обработчик исходящих сообщений.
Проверка отдельных известных конструкций не равна полной проверке всех ответов ИИ.

## Спринт 2 — новая ситуация и завершение дня (PATCH-46)

1. Разделить завершение основной дневной работы и доступность новой ситуации.
2. Создавать отдельную сессию без автоматического переноса прежней версии причин.
3. Всегда открывать подробности именно последнего разбора.
4. Проверить полный добровольный эксперимент после завершения основного дня.

Реализовано: дополнительная ситуация получает сохранённый case_id и отдельную
текущую версию причин; последние 20 разборов сохранены отдельно от текущего.
Старые результаты упражнений и события не удаляются. Признак дополнительного
разбора теперь сохраняется в базе, а ответы на уточнения не начинают новый кейс.
Дневная программа и план не сбрасываются. Подробнее работает как информационный
экран без изменения текущего вопроса. Добровольное действие использует навык из
нового разбора; выполнение не объявляется доказательством полезности.
Миграция добавляет поля без удаления старых данных.

## Спринт 3 — понимание запроса (PATCH-47)

1. Различать задачи, эмоциональное состояние, здоровье, кризис, отношения и другое.
2. Отвечать на текущий запрос без диагнозов и вывода «ленивый».
3. Дожидаться ответа на уточнение, выбирать упражнение по описанной трудности.
4. Уточнять устройство при отвлечении и предлагать подходящий шаг.

Реализован отдельный путь для состояния, здоровья, отношений и неясного запроса.
Кризисный обработчик сохраняет приоритет. Уточняющий вопрос сохраняется между
сообщениями; разбор задачи начинается только после выбора пользователя.
Вопросы здоровья не передаются в обычный анализ прокрастинации и не получают
назначения препаратов. Новые сведения хранятся как короткие категории, без полного
текста пользователя. Отвлечение на сайтах не означает автоматически телефон:
при неизвестном устройстве бот спрашивает и ждёт ответа. Для компьютера первый
шаг — одно рабочее окно, для телефона — убрать его из руки. При тревоге без явно
описанной телесной нагрузки первый шаг — проверка опасения, при перегрузе —
видимый следующий шаг. Самооценка «ленивый» не становится выводом бота.

Границы: маршрутизация по явным словам не покрывает все формулировки. Бот уточняет
неясные запросы; живое тестирование новых сценариев ещё требуется.
Основания для медицинских формулировок (проверены 3 октября 2026):
https://www.nhs.uk/mental-health/conditions/depression-in-adults/diagnosis/
https://www.nhs.uk/medicines/antidepressants/

## Спринт 4 — результат и следующий шаг

1. Не спрашивать повторно, выполнено ли действие, после кнопки результата.
2. Различать выполнение, самочувствие, продолжение дела и возвращение к нему.
3. Учитывать отрицательный результат и согласовать все выводы дня.
4. Упростить итог и предлагать подходящий следующий шаг с возможностью отказаться.

## Спринт 5 — предложения помощи

1. После пользы в первый день показывать мягкое предложение без завершения работы.
2. На третий день использовать только подтверждённые наблюдения; в финале сначала итог.
3. Группа — €240; индивидуальная работа — от €99/месяц, цены из конфигурации.
4. Сохранять точное место разговора при открытии предложения и возвращаться туда.

Цены и последовательность из нового задания заменяют прежние рекомендации отчёта
LAUNCH_REVIEW_2026-10-01.md. До спринта 5 коммерческие тексты ещё не обновлены.
Перед публичным запуском нужны все обязательные сценарии из задания и живой тест Telegram.

### PATCH-48 — короткий спринт 4а

1. После кнопки «Сделал» сразу спрашиваем о пользе; не повторяем вопрос о выполнении.
2. «Стало хуже» сохраняется как отрицательный результат во всех расчётах обратной связи, включая личную рабочую модель. В сообщении прямо называем ухудшение и предлагаем остановиться или выбрать другой вариант.
3. В истории попытки отдельно сохраняются выполнение, частичное выполнение, изменение состояния, продолжение задачи, возврат после отвлечения (только когда такой контекст известен), помеха и контекст. Отрицательные ответы учитываются защитой от повторения способа.
4. Итог дня больше не приписывает пользу уменьшению шага при отсутствии таких попыток.

Это часть четвёртого спринта. Ещё нужны единый расчёт выводов для всех дневных экранов, свободный ответ о частичном результате и та же обратная связь после дополнительного упражнения в закрытом дне. Коммерческий спринт остаётся следующим после завершения этих сценариев. Производство не обновлено.
