# MASTER PATCH — Skiller Behavior Engine

## 1. Короткий аудит: что уже реализовано

В репозитории уже есть рабочая основа коммерческого Telegram-продукта против прокрастинации:

- **Telegram-интерфейс и сценарии запуска**: основной entrypoint, роутинг, клавиатуры, кризисные и платежные ветки находятся в `bot.py`.
- **UI-независимое ядро тренировки**: `core/engine.py` уже отделяет выбор навыка, карточку навыка, обработку результата и offer от Telegram-слоя.
- **Модуль прокрастинации как первый трек**: каталог и планы в `skills.py` используют `track="procrastination"`, а будущие треки уже перечислены как disabled в `core/engine.py`.
- **База микронавыков**: `skills.py` содержит существующий каталог навыков, core-группы, недельные шаблоны и продуктовые навыки.
- **Диагностика/профиль/карта пользователя**: `db.py` хранит `profile_json`, события модели пользователя, карту, динамические списки успешных/неуспешных навыков и безопасные формулировки гипотез.
- **Ежедневная логика**: есть день, lock дневного core-навыка, лимит кругов за день, morning/evening state-поля, возвраты и stop-состояния.
- **Обратная связь и события**: есть `user_feedback`, `action_events`, счетчики попыток, результаты skill-result и smoke-тесты для feedback/action metrics.
- **Безопасность**: есть crisis/safety mode, кризисные кнопки и блокировка стандартной продуктивной тренировки при risk-сигналах.
- **Монетизация MVP**: есть trial/paid статусы, payment URL env-переменные, offer после первых дней и тестовый payment QA режим.
- **Подготовка к запуску**: есть README, checklist, QA-документы, Dockerfile, smoke/regression scripts.

## 2. Что реализовано частично

- **Behavior Engine как явная продуктовая сущность**: логика уже выделена в `core/engine.py`, но до патча не было явного списка сущностей, нормализованного skill schema и структурированного experiment payload.
- **Навыки как эксперименты**: тексты уже говорят без давления, но карточка навыка не возвращала структурированный объект эксперимента вместе с рекомендацией.
- **Структурирование 300 навыков**: каталог большой, но legacy-записи имеют разные поля. Нужен нормализатор, который не ломает старую базу и постепенно приводит навыки к обязательной схеме.
- **Механизмы навыков**: часть навыков имеет `mechanism`, часть определяется через группы/планы. Нужна единая fallback-карта barrier → mechanism.
- **Персональная модель**: данные и события уже есть, но следующий шаг — использовать structured experiments для рекомендаций не только по спискам профиля.
- **Вечерний отчет**: состояния и данные есть, но нужен общий renderer по структурированным экспериментам.
- **Единое ядро для будущего приложения**: архитектурно возможно, но публичного API/контракта для мобильного клиента пока нет.

## 3. Что пока не реализовано

- Полная валидация всех ~300 навыков на обязательные поля мастер-документа.
- Рекомендательная модель с вероятностью выполнения и learning loop на истории экспериментов.
- Полный structured storage для `behavior_experiments` отдельной таблицей.
- Недельный отчет и персональная карта механизмов на основе агрегированных experiment episodes.
- Пользовательское согласие/удаление данных как отдельный прозрачный продуктовый flow.
- Реальная платежная webhook-проверка провайдера.
- Мобильное приложение, API/SDK, кабинет специалистов и новые модули.

## 4. Мастер-патч, примененный сейчас

Этот патч не переписывает Skiller. Он добавляет тонкий слой Behavior Engine поверх существующего Telegram MVP:

1. Добавлен явный контракт сущностей Behavior Engine.
2. Добавлены варианты короткой feedback-схемы эксперимента.
3. Добавлена карта barrier → mechanism и skill → barrier для первых core-навыков.
4. Добавлен `normalize_micro_skill()` — нормализатор legacy-навыка к обязательным полям без мутации старого каталога.
5. Добавлен `build_behavior_experiment()` — структурированный объект `context → barrier → intervention → result`.
6. Карточка навыка теперь возвращает `experiment` в screen payload и пишет его в событие `skill_card_shown`.
7. Добавлен `build_evening_report_from_experiments()` — короткий, неоценочный отчет по экспериментам.
